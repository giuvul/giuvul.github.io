Data Governance

A promise
the data keeps

Data quality does not fail loudly. Nothing crashes; the numbers simply become wrong, and somebody notices weeks later in a meeting. The only defence is to write down every assumption about the data as something a machine can check, and to check it on a schedule.

System
Passenger profiling platform
Scale
43 contracts, hourly and on every write
Role
Sole architect and engineer
Stack
YAML / SQL / CloudWatch
01

The challenge

The product's output is inference, so a wrong value does not look wrong. Upstream feeds changed formats without warning and nothing objected.

02

The approach

Move every assumption out of the code and into a declared registry that runs on a schedule, records its verdicts, and reports its own health.

03

The result

Whole classes of silent corruption are now caught before a customer sees them, and the registry doubles as the written definition of what each field means.
